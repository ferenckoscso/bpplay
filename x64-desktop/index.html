Hardware

Any x86_64 PC. Bring your own DAC

Unlike the sealed Pi appliance, this trial runs on unknown, unfamiliar hardware; so DSD/DoP support and tuning depend on what you plug in.

Machine Any x86_64 PC, or Intel Mac Boot UEFI/BIOS boot from USB OS Debian 13 "trixie", console only Storage USB stick, 8 GB minimum RAM 4 GB practical minimum, the OS boots into memory DAC ALSA-compatible USB DAC, or built-in audio Network not required for playback itself
What's stored on the stick. Since the OS now runs entirely from RAM, the stick only holds a small settings area (player settings, network settings, the first-boot measurement result); there is no large persistent partition to grow any more. Your music itself is never stored on the stick; drag it in from a connected drive or network share.

1What you'll need

  • A USB stick, at least 8 GB (its current contents will be erased).
  • Balena Etcher (recommended, free, identical on Mac and Windows).
  • The bpplay-desktop-x86_64.img.gz file (Google Drive link, above).
  • A monitor, keyboard and mouse on the machine itself; this edition needs no second device and no network connection to play music.

The downloaded .gz file is about 1.8 GB. Unlike earlier disk-mode images, this edition boots entirely into RAM: the stick only holds a small settings area (your preferences and the trial countdown live there), not a large persistent partition.

2Writing the image to the USB stick

A) Balena Etcher: recommended for everyone
  • Download and install Balena Etcher, plug in the stick.
  • Open Etcher, "Flash from file", select the downloaded .img.gz (Etcher decompresses it automatically while writing).
  • "Select target": the USB stick; double-check the size (GB) if several drives are connected.
  • "Flash!": erases the stick and writes the image, a few minutes.
B) dd: for advanced Linux/Mac users
Important safety warning: dd irreversibly overwrites the target device. If you specify the wrong device, you will lose data. Always double-check the device name before pressing Enter.
Linux / macOS
# Linux, after plugging in, identify the new entry:
lsblk
gunzip -c bpplay-desktop-x86_64.img.gz | sudo dd of=/dev/sdX bs=4M status=progress
sync
# macOS, after plugging in, identify the new device (e.g. /dev/disk4):
diskutil list
diskutil unmountDisk /dev/diskN
gunzip -c bpplay-desktop-x86_64.img.gz | sudo dd of=/dev/rdiskN bs=4m
sync
diskutil eject /dev/diskN

(dd is not available on Windows; Etcher is the only recommended path there.)

3Booting from the USB stick

Mac (Intel)
  1. Fully shut down the machine (not sleep).
  2. As it powers on, immediately press and hold Option (⌥).
  3. Select the USB stick from the boot menu (usually labeled "EFI Boot").

If the Mac doesn't offer the USB as a boot option: on Intel Macs, the Startup Security Utility may be set to "Full Security", which blocks external boot. Restart holding ⌘+R to enter Recovery, then select "No Security" or "Medium Security" and enable "Allow booting from external media".

Windows
  1. Fully shut down the machine.
  2. As it powers on, repeatedly press the boot-menu key; commonly F12, F2, Esc or Del depending on the manufacturer.
  3. Select the USB stick from the list.

If Windows won't boot the USB: you may need to disable Secure Boot in the BIOS/UEFI, or enable Legacy/CSM or "boot from removable media". A UEFI BIOS is recommended over legacy BIOS for the smoothest boot. Your existing Windows installation on the machine's own drive is never touched; this edition runs entirely from the USB stick.

4First boot and playback

The stick boots straight into a normal desktop, with automatic login; no password to type. A "bpplay" icon sits on the desktop, labeled "drag a music file or album here". Open a file manager window (already on the desktop/taskbar), navigate to your music, on a connected USB drive, or already copied onto the stick, and drag a track or a whole album folder onto the bpplay icon.

This opens a small terminal window showing bpplay's own format check and playback controls:

KeyFunction
nNext track
bPrevious track
SpacePause / resume
qStop playback; closes the window

Dropping a new file or folder onto the icon while something is already playing starts a fresh playback window; the previous one keeps running until you stop it or close it, so avoid overlapping playback unintentionally.

5What runs in the background

Each time you start playback, bptune disables Turbo Boost/Precision Boost for that session.

Not locked down: unlike the kiosk edition, this is a normal, usable desktop: a terminal, file manager and other applications are available, and the machine does not shut itself down when you close a playback window. The tradeoff for that convenience is the smaller jitter improvement described above.

Quiet profile

When the quiet profile is on, the following background services are stopped for playback: cron, avahi, rpcbind, polkit, udisks2, the periodic maintenance timers, the udev control sockets, the user session manager, and Wi-Fi supplicant services when no Wi-Fi connection is active. These are never stopped: journald, ssh, NetworkManager, dbus and logind. If any of them is not running after the stop, everything is restored at once. The profile is switched off again when playback ends. On the desktop edition the profile stops a shorter list, so that the graphical session stays open.

What belongs to the music selector

Full Pure, the selectable CPU isolation mode (c), the global search and the g report belong to the music selector of the kiosk editions. The desktop edition uses its own file manager. A desktop icon opens the machine survey report (bptune survey) in a terminal.

Boot-time measurement

bptune measures the CPU cores at boot and chooses the playback core.

Language editions

bpplay is released in Hungarian (HU) and English (EN) editions. The language is fixed in the image: it sets the texts of the music selector and of bptune, the default music folder (Zenék in the HU edition, Music in the EN edition) and the time zone (Europe/Budapest in HU, UTC in EN). On the desktop edition the keyboard layout follows the language (hu or us).

6Trial period: 15 days

This is a time-limited trial, valid for 15 days from your first real boot. The countdown is tied to the USB stick itself, not the machine you boot it on; so if you try it on several machines, the remaining time carries over.

A new image is a new trial: if the image is newer than the stored start, the 15 days count from the image. An image built more than 90 days before it is first started will not start. The desktop edition has no music selector, so there is no countdown line on screen.

  • Turning back the clock does not extend the trial; the system detects this.
  • On expiry, the machine shuts down automatically after a short message; this is not a bug, it is the trial's intended end (the same thing happens if you press q at the top level).
  • The trial is not extendable; to try it again after it expires, get in touch with whoever gave you the USB stick for a fresh image.

7Troubleshooting

SymptomSolution
Nothing happens, blank/black screenWait about 30 seconds; first boot can take a bit longer. If still blank, re-write the stick.
Nothing happens when dropping a fileCheck the file is a supported format (WAV, FLAC, ALAC/M4A, AIFF/AIFC, DSF).
No sound during playbackCheck the DAC/sound card is connected and try a different USB port.
Playback seems unusually quietbpplay intentionally never touches any volume control (always bit-perfect); if the DAC's own firmware-level volume was previously set low by other software, that setting persists under bpplay too. Check your OS's audio mixer and set the DAC's own volume to maximum (0 dB). Currently, XMOS and Amanero USB interfaces are considered supported in this regard; other, more general-purpose USB audio interface chips may have a software volume control, and can be affected.

Machine shuts down after a short messageThe 15-day trial has expired; contact whoever gave you the stick.

If anything doesn't work as described, please send: which machine you tried it on (Mac/Windows, model), the exact error message (if any), and what you were doing when it happened. You can also ask the experimental bpplay chat assistant, which is based on more than 100 bpplay/bptune documents and links (a Google sign-in is required): open the chat.

8What's new: RC21 and RC22

RC21

  • Full Pure (u key): the network is switched off at link level while the music plays.
  • Global search across all drives with the / key, with a stored index; playback starts only after the first indexing pass.
  • The g machine survey: report texts, the CPU isolation mode screen, a short summary at the first start, the Intel management engine runtime state, USB controllers.
  • Trial: the settings area is used only on the boot stick, and a new image is a new trial. A new image's first boot does not take over a settings area left by another image, so the trial starts from the first boot.
  • A drive that disappeared behind a search result is handled with a message; hidden and ._ files are not indexed.
  • The now-playing line keeps Artist and Title visible when the album name is long; reaching the folder or row limit is reported (bpplay 1.5.8 and 1.5.9). When bpplay's output is piped, the line fits the terminal width (bpplay 1.5.15).
  • ID3 tags are read from AIFF and WAV files, with the artist per track (bpplay 1.5.10 and 1.5.12).
  • The output selector can be canceled with q or Esc.
  • SACD ISO: more reliable track paths and indexing; folder mode accepts DFF files and SACD ISO tracks (bpplay 1.5.13).
  • DSD files: the file's own end padding is no longer played as audio.
  • The English image contains no Hungarian text, and the default music folder follows the image language (Music in EN, Zenék in HU).

RC22

  • Full Pure and repeat mode are kept apart: repeat blocks Full Pure, and the other way round.
  • The output chosen in the selector is remembered in the settings area; short help for a and n; an SSH banner on the Raspberry Pi; the HU desktop edition gets the Hungarian keyboard layout.
  • The Hungarian image runs in local time (Europe/Budapest); the English image stays on UTC.
  • The g report has a DAC section: the formats the DAC advertises, the format used during playback, and the mixer and mute state.
  • Desktop edition: the quiet profile stops a shorter list, so that the graphical session stays open.
  • bpplay 1.5.16: no hang with a non-terminal, open input, and a clean stop on TERM, INT and HUP. bpplay 1.5.17: the escape sequence of an arrow key no longer triggers a player command.
  • bpplay 1.5.18: on TEAC/Esoteric (0x0644) and Luxman (0x3255) DACs, 16 and 24 bit sources are sent in their own width first (S16 or S24 packed), with 32 bit as fallback; other DACs keep 32 bit first.
  • Raspberry Pi: the remaining trial time is shown in the music selector header line (Trial: N days left).
  • The short summary is no longer truncated; the 5 minute NAS re-check is gone; the R key is gone from the drive selector, and an already mounted drive asks whether to check for changes.
  • The x key excludes a drive from search and indexing only; the drive stays in the selector with the mark (excluded from search), and the same key switches it back.
  • bptune 0.3.8: the Renesas hint appears only without a working device, Bay Trail TXE is recognized, and a firmware version of 0.0.0.0 is shown as unknown.
