WHAT YOU GETAMIT KAPSZ

Your own personal music box.Egy komplett hi-fi, lezárva, kiosk módban.

The appliance edition turns the Pi into a dedicated listening machine: it boots straight into the music selector, and everything technical is either automatic or already factory-configured.A készüléki kiadás a Pi-t dedikált zenehallgatási géppé alakítja: egyenesen a zeneválasztóba bootol, és minden technikai részlet vagy automatikus, vagy gyárilag be van állítva.

01 · KIOSK

Sealed kiosk modeZárt kiosk mód

The device boots straight into the music selector. You never see a login, a terminal or admin rights; deliberately. A handful of keys is enough: arrows, Enter, Space, Esc.A készülék egyenesen a zeneválasztóba bootol. Bejelentkezést, parancssort és admin jogot szándékosan nem látsz. Néhány billentyű elég: nyilak, Enter, Space, Esc.

02 · INTEGER

Bit-perfect, by contractBithelyes, szerződésszerűen

Integer mode whenever the DAC allows it: the samples in the file reach the sound card without a single bit shift. If a compromise is ever forced, bpplay says so on screen; it never stays silent about it.Integer mode, amint a DAC engedi: a fájl mintái egyetlen bitsift nélkül érnek a hangkártyához. Ha mégis kompromisszum kényszerül, a bpplay kiírja; sosem hallgat róla.

03 · DSD

Native DSD and DoPNatív DSD és DoP

DSD data goes to the DAC unpackaged when the chip supports it. Support depends on the DAC, not on the Pi; before planning DSD, check the tested-hardware table below.A DSD adat csomagolatlanul megy a DAC-hoz, ha a chip támogatja. A támogatás a DAC-on múlik, nem a Pi-n; DSD előtt nézd meg az alábbi tesztelt-hardver táblázatot.

04 · BPTUNE

bptune under the hoodbptune a motorháztető alatt

A PREEMPT_RT kernel and system tuning for low-latency, glitch-free playback; installed and configured by the factory installer. As an end user, there is nothing for you to do with it.PREEMPT_RT kernel és rendszerhangolás a késleltetésmentes, kihagyásmentes lejátszásért; a gyári telepítő már beállította. Végfelhasználóként nincs teendőd vele.

1IntroductionBevezetés

1.1 What is bpplay?1.1 Mi az a bpplay?

bpplay is a command-line, bit-perfect audio file player application for Linux and macOS. It has no graphical interface, no volume control, no equalizer; deliberately. Its goal is one single thing: to deliver the contents of the music file unchanged, via the shortest possible path with the fewest conversion steps, to the DAC (digital-to-analog converter).A bpplay parancssori, bithelyes zenefájl-lejátszó alkalmazás Linuxra és macOS-re. Nincs grafikus felülete, hangerőszabályozása, hangszínszabályozója; szándékosan. Célja egyetlen egy dolog: a zenefájl tartalmát változatlanul juttatnia el, a lehető legrövidebb úton, a lehető legkevesebb konverziós lépéssel, a DAC-hoz (digitál-analóg átalakítóhoz).

Whenever possible, the program plays in so-called "integer mode", which means the integers stored in the file (integer samples) reach the sound card without a single bit shift or conversion. When this is not possible (e.g. the source is in float format, or the DAC does not support the exact bit depth of the source), the program always states this clearly; it never stays silent about being forced into a compromise.Amikor csak lehetséges, a program úgynevezett „integer mode"-ban játszik: ilyenkor a fájlban tárolt egész számok (integer minták) egyetlen biteltolás vagy konverzió nélkül érik el a hangkártyát. Ha ez nem lehetséges (pl. a forrás float formátumú, vagy a DAC nem támogatja a forrás pontos bitmélységét), a program ezt mindig egyértelműen közli; sosem hallgat arról, hogy kompromisszumra kényszerült.

In the appliance edition the end user never launches this program directly; instead, the zenevalaszto.py Python script invokes it in the background for the selected track(s) (see Chapter 3).A készüléki kiadásban a végfelhasználó soha nem indítja közvetlenül ezt a programot; helyette a zenevalaszto.py Python script hívja meg a háttérben a kijelölt szám(ok)hoz (ld. 3. fejezet).

This is the most important design principle of bpplay. If, for any reason, the program cannot achieve exactly the sample rate, bit depth or format the file requires, it:Ez a bpplay legfontosabb tervezési elve. Ha bármely okból a program nem tudja pontosan elérni a fájl által igényelt mintavételi frekvenciát, bitmélységet vagy formátumot, akkor:

  • clearly states on screen what happened;egyértelműen kiírja a képernyőre, mi történt;

1.3 Native DSD and DoP1.3 Natív DSD és DoP

DSD (Direct Stream Digital) is a high-resolution audio format used by SACDs and some downloadable/streamed releases. Many players repackage DSD data into PCM frames (DoP, DSD over PCM) before sending it to the DAC. bpplay can send DSD data directly, without repackaging, if the DAC supports it; this is called native DSD playback.A DSD (Direct Stream Digital) nagyfelbontású audioformátum, amelyet SACD-k és egyes letölthető/streamelt kiadások használnak. Sok lejátszó a DAC-nak küldés előtt PCM keretekbe csomagolja át a DSD adatot (DoP, DSD over PCM). A bpplay a DSD adatot közvetlenül, átcsomagolás nélkül is elküldheti, ha a DAC támogatja; ezt nevezzük natív DSD lejátszásnak.

Important, Pi-specific limitation.Fontos, Pi-specifikus korlát.
Native DSD and DoP support depends entirely on the chip of the connected DAC/USB interface and on the design of the DAC, not on the Raspberry Pi. Tested hardware gave different results; before planning DSD playback with a given device, see the hardware table in Chapter 4.A natív DSD és DoP támogatás teljes egészében a csatlakoztatott DAC/USB interfész chipétől és a DAC felépítésétől függ, nem a Raspberry Pi-től. A tesztelt hardverek eltérő eredményt adtak; adott eszközzel DSD lejátszás tervezése előtt ld. a 4. fejezet hardvertáblázatát.

5Appendix: technical backgroundFüggelék: technikai háttér

5.1 The signal path philosophy5.1 A jelút filozófiája

bpplay's design goal is for sound to travel from the file's loading into memory to the DAC through the fewest, best-documented steps possible. When an integer source meets an integer DAC format, this means zero arithmetic conversion.A bpplay tervezési célja, hogy a hang a fájl memóriába töltésétől a DAC-ig a lehető legkevesebb, legszabályozottabban dokumentált lépésen keresztül haladjon. Amikor integer forrás találkozik integer DAC formátummal, ez nulla aritmetikai konverziót jelent.

5.2 The role of the sound driver5.2 A hangmeghajtó szerepe

The phrase "the sound driver performs the last step" in the signal-path messages refers to the audio subsystem of the underlying operating system (ALSA on Linux); a platform-independent, precise wording.Az „a hangmeghajtó végzi az utolsó lépést" kifejezés a jelút-üzenetekben az operációs rendszer hangalrendszerére utal (Linuxon az ALSA); platformfüggetlen, precíz megfogalmazás.
