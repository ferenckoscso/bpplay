Requesting a bpplay license

A purchased bpplay license is issued for one computer, and works on that computer without a time limit. To prepare your own, machine-bound image, we need the computer's machine ID. This guide describes, step by step, how to read the ID, how to send it, and how to write your own image.

What you need

  • The computer that will run bpplay (an x64 PC or a Raspberry Pi). The license is issued for this computer.
  • A USB stick (x64) or an SD card (Raspberry Pi) to write the image to.
  • A computer or phone with an SSH client to operate the kiosk, just as with the trial edition.
  • The e-mail address used for the purchase. The license must be requested from this address, and the download link for your own image is sent to it.
Note: the license is bound to the computer, not to the USB stick or the card. Your own image can later be written to another stick as well, and it works the same way on the same computer.

The process in five steps

  1. Write and start the bpplay trial image on the computer the license is for.
  2. Read the machine ID in the kiosk menu with the g (report) key, and copy it.
  3. Send the ID by e-mail, from the e-mail address used for the purchase.
  4. We prepare your own, machine-bound image and reply with the download link.
  5. Write your own image to the stick or card in place of the trial, and start the computer. From then on there is no trial period.

The trial image can be used in the meantime: it works fully for 15 days from its first start.

Step 1: reading the machine ID

The machine ID is shown in the trial image's report as text, so it can simply be copied.

  1. Download the latest bpplay trial image and write it to the stick or card as described in the manual.
  2. Start the image on the computer the license is for. The ID belongs to the computer the image runs on.
  3. Log in to the kiosk over SSH, as described in the manual: ssh kiosk@<host name>.local
  4. In the main menu, press the g key (report).
  5. At the top of the report:
Machine binding ID (send it to us if you request a license):
xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx
  1. Select and copy the eight groups separated by spaces. All eight groups are needed (64 characters in total, digits and the letters a to f).
  2. Press Esc to return to the main menu.
Important: copy the ID, do not retype it. If a single character differs, the license will not work on the computer.
Note: if instead of the ID the report says (this machine cannot be licensed: the board factory identifier is missing or invalid), no license can be issued for this computer. In that case, please contact support@bpplay.hu.

Step 2: requesting the license

Request the license by e-mail at support@bpplay.hu, from the e-mail address used for the purchase, in this form:

Subject: bpplay license request

Computer type: x64 PC / Raspberry Pi
Machine binding ID:
xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx
  • Paste the ID exactly as it was copied from the report, spaces included.
  • One e-mail should cover one computer. For several licenses, send a separate e-mail per computer, each with its own ID.
  • You will receive a download link to your own image, with its checksum (sha256) and your customer ID. Please keep the customer ID: you will need it if the motherboard or the Raspberry Pi is replaced.

Step 3: writing your own image and the first start

  1. Write the downloaded image to the stick or card the same way as the trial image, as described in the manual. This overwrites the trial.
  2. Start the computer from the stick or card, as before.
  3. The first start may take a little longer than usual, because the stick's state partition (and on a Raspberry Pi the computer's own SSH key) is created then.
  4. Log in over SSH as usual. The kiosk shows the same menu as the trial, but no longer counts down a trial period.
Important: at the first login to the new image, your SSH client may warn that the host key has changed ("REMOTE HOST IDENTIFICATION HAS CHANGED"). This is expected with a new image. After removing the old key, logging in works: ssh-keygen -R <host name>.local
Note: at the first start of the new image, the earlier state stored on the stick or card is not carried over; the system creates everything again. Files on your music drives are not affected.
Note: it is worth keeping a backup copy of your downloaded image. It can be written again at any time on the same computer.

If the computer does not start: error codes and what to do

If the license check fails, the computer does not start, it cannot be reached over SSH, and a monitor connected to it shows a message like this (example for the id_mismatch code):

bpplay license check failed, the machine cannot start.

Code: id_mismatch
The license is for a different machine. After a motherboard replacement, request a new license: send the machine ID and the code.

Machine ID (send it together with the code):
xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx xxxxxxxx

The machine will shut down shortly.

The message is visible for about 150 seconds, then the computer switches off. During this time, write down or photograph the error code and the ID, and send them to support@bpplay.hu from the e-mail address used for the purchase.

Computer without a monitor: if no monitor is connected (common with a Raspberry Pi), the message cannot be seen. The sign is that after switching on, the computer cannot be reached over SSH, and it switches off a few minutes later. What to do:

  1. Write your own image again from the downloaded file, and restart the computer.
  2. If the problem remains, write and start the trial image, and read the machine ID from its g report, just as when requesting the license. This shows whether the license was issued for this computer.
  3. Send the ID you read, together with a description of what happened, to support@bpplay.hu from the e-mail address used for the purchase.

If a monitor is at hand, connect it to the computer's HDMI output to read the error code and the ID directly.

Error codeMeaningWhat to do
license_missingThe image contains no license.Write your own, machine-bound image, not the common image without a license.
id_mismatchThe license is for another computer.If the image was moved to another computer, use it on your own computer. After a motherboard or Raspberry Pi replacement a new license is needed (see the next section).
scheme_mismatchThe license is for a different type of computer (a Raspberry Pi instead of x64, or the other way round).Request the license for this computer, with the ID and the error code.
not_licensable, not_licensable_piThe computer's factory identifier is missing or invalid.No license can be issued for this computer. Help is available at support@bpplay.hu.
license_invalid, sig_invalid, format_unsupported, unknown_keyThe license file is damaged, or does not belong to this release.Write your own image again from the downloaded file. If the problem remains, send the error code.
verify_error, internal_errorThe check did not run because of a technical error.Restart the computer. If the problem remains, send the error code.
Note: the license check needs no internet connection, and the computer's clock does not matter. The license does not expire.

Replacing the computer, the motherboard, or moving the license

On an x64 computer the machine ID is derived from the motherboard's factory identifier, on a Raspberry Pi from the Pi's factory serial number. Replacing memory, disks, the DAC or the USB stick does not change it.

CaseWhat happens
Motherboard replacement (x64)The computer stops with the id_mismatch error code. The license is reissued free of charge for the new ID: send the error code, the new ID and your customer ID, from the e-mail address used for the purchase.
Raspberry Pi replacementThe computer stops with the id_mismatch error code. A new license can be requested for the new Pi's ID in the same way, with the error code, the new ID and your customer ID.
Moving to another, existing computerThe license cannot be moved. The other computer needs its own license.
Writing your own image to another stickWorks on the same computer without any problem; no new license is needed.

Frequently asked questions

The trial period ended before I read the ID. What should I do? The trial period cannot be extended. Download and write the latest bpplay trial release; the ID can be read from it in the same way.

How long can the downloaded trial image be used? The trial period is 15 days from the first start.

Is an internet connection needed to use my own image? No. The computer checks the license locally, without internet, and bpplay sends no data anywhere.

What if I have several computers? Each computer has its own license and its own image. Read and send the ID separately for each computer.

Does my own image work on another computer? No. On another computer the image stops with the id_mismatch error code, so there is no point in passing it on to someone else.

Are my music files and drives kept after writing my own image? Yes. Writing the image only overwrites the contents of the stick or card; it does not touch your music drives.

What data we keep

bpplay itself sends no data: there is no telemetry and no online check. You read the machine ID yourself and send it to us when you request a license.

About issued licenses, we keep only this:

  • the customer ID (a serial number and a short code derived from the buyer's name, for example BP-2026-0002-SmithJ),
  • the machine ID,
  • the date the license was issued,
  • the ID of the signing key,
  • the checksum (sha256) of the issued license file.

The record contains no full name and no e-mail address: the buyer is referred to only by the short code in the customer ID. The sender address of the license request e-mail is used to identify the purchase and is not entered in the license record. The machine ID is a one-way digest of the computer's factory data; the original data cannot be derived from it.
