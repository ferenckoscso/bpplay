Hardware

Any x86_64 PC. Bring your own DAC

Unlike the sealed Pi appliance, this trial runs on unknown, unfamiliar hardware; so DSD/DoP support and tuning depend on what you plug in.

Machine Any x86_64 PC, or Intel Mac Boot UEFI/BIOS boot from USB OS Debian 13 "trixie", console only Storage USB stick, 4 GB minimum (kiosk) / 8 GB (desktop) RAM 4 GB practical minimum, the OS boots into memory DAC ALSA-compatible USB DAC, or built-in audio Network wired Ethernet only; required for SSH control
What's stored on the stick. Since the OS now runs entirely from RAM, the stick only holds a small settings area (player settings, network settings, the SSH host key, the first-boot measurement result); there is no large persistent partition to grow any more. Your music itself is never stored on the stick; it is played from a network share or a separate USB drive.

1What you'll need

  • A USB stick, at least 4 GB (its current contents will be erased).
  • Balena Etcher (recommended, free, identical on Mac and Windows).
  • The RAM-boot kiosk image, the English kiosk image (a .img.gz file) (Google Drive link, above).
  • A wired Ethernet connection for the machine (Wi-Fi is deliberately disabled); required, since the music selector is reached over an SSH connection to the machine (see 3), without it you cannot select or play anything.
  • An SSH app on your own computer, tablet or phone (see 3); no monitor or keyboard is needed on the machine itself.
  • 4 GB of RAM, practical minimum: this edition boots the whole OS into memory, not just the live filesystem.
  • An ALSA-compatible USB DAC, or the machine's built-in audio output if none is connected. Connect the DAC directly to the machine, not through a USB hub; a hub can make the connection unreliable.

Supported file formats: WAV, FLAC, ALAC (M4A), AIFF/AIFC, DSD (DSF/DFF, natively and via DoP), and SACD ISO (the disc's stereo layer, DST-compressed or uncompressed; see section 4).

The downloaded .gz file is about 960 MB. Once written, the stick holds only the boot system plus a small settings area (your player/network settings, favorites, saved playlists, SSH host key and the trial countdown live here, and survive a reboot): there is no large persistent partition any more, the OS itself now runs from RAM.

2Writing the image to the USB stick

A) Balena Etcher: recommended for everyone

  • Download and install Balena Etcher, plug in the stick.
  • Open Etcher, "Flash from file", select the downloaded .img.gz (Etcher decompresses it automatically while writing).
  • "Select target": the USB stick; double-check the size (GB) if several drives are connected.
  • "Flash!": erases the stick and writes the image, a few minutes.

B) dd: for advanced Linux/Mac users

Important safety warning: dd irreversibly overwrites the target device. If you specify the wrong device, you will lose data. Always double-check the device name before pressing Enter.
Linux / macOS
# Linux, after plugging in, identify the new entry:
lsblk
gunzip -c bpplay-kiosk-x86_64.img.gz | sudo dd of=/dev/sdX bs=4M status=progress
sync
# macOS, after plugging in, identify the new device (e.g. /dev/disk4):
diskutil list
diskutil unmountDisk /dev/diskN
gunzip -c bpplay-kiosk-x86_64.img.gz | sudo dd of=/dev/rdiskN bs=4m
sync
diskutil eject /dev/diskN

(dd is not available on Windows; Etcher is the only recommended path there.)

3Booting from the USB stick

Booting from the stick does not start the system installed on the machine (for example Windows). The kiosk runs from the stick and from RAM, and keeps its settings only in a small settings area on the stick; the drives you choose in the music selector are mounted read-only. During playback the quiet profile only puts the drives connected to the machine, internal and external USB, into a low-power state (see 5.2). To return to your usual system, shut the machine down, remove the stick and start it normally.

Mac (Intel)

  1. Fully shut down the machine (not sleep).
  2. As it powers on, immediately press and hold Option (⌥).
  3. Select the USB stick from the boot menu (usually labeled "EFI Boot").

If the Mac doesn't offer the USB as a boot option: on Intel Macs, the Startup Security Utility may be set to "Full Security", which blocks external boot. Restart holding ⌘+R to enter Recovery, then select "No Security" or "Medium Security" and enable "Allow booting from external media".

Windows

  1. Fully shut down the machine.
  2. As it powers on, repeatedly press the boot-menu key; commonly F12, F2, Esc or Del depending on the manufacturer.
  3. Select the USB stick from the list.

If Windows won't boot the USB: you may need to disable Secure Boot in the BIOS/UEFI, or enable Legacy/CSM or "boot from removable media". A UEFI BIOS is recommended over legacy BIOS for the smoothest boot.

3.1 Connecting via SSH

The machine boots straight into the music selector, with no login; you simply connect to it over SSH. You never see a command line, terminal or login prompt on the machine's own screen; if you connect a monitor anyway, it stays blank. From your own device, open an SSH app and connect to kiosk@bpplay-kiosk-en-XXXX.local (XXXX the last four hex digits of the MAC address): this works even without a router or DHCP, straight over a single Ethernet cable between just the two machines. If .local names don't resolve on your network, note the machine's IP address instead (shown briefly on screen right after boot, before it would otherwise show a login prompt) and connect to kiosk@ that address. When the SSH app asks for a password, it is bitperfectsound; both the user name and the password use only characters that sit in the same place, without Shift, on the common keyboard layouts (QWERTY, QWERTZ, AZERTY), so the login works even if your computer's layout differs from what you're used to. The music selector screen then appears; nothing else needs to be typed.

macOS / Linux: Terminal + ssh Windows 10/11: OpenSSH · PuTTY Android: Termux · JuiceSSH · ConnectBot iOS / iPadOS: Termius · Blink Shell
your-computer, Terminal
you@your-mac ~ % ssh kiosk@bpplay-kiosk-en-3f2a.local
Wired Ethernet only. This kiosk edition deliberately uses only a wired Ethernet connection, for determinism and sound quality; Wi-Fi is disabled by design. Plug in a cable before booting, and keep it connected for the entire listening session; the SSH connection keeps the music selector alive through it. If the network drops, the connection drops too, and you need to reconnect.

4.1 Full Pure

Full Pure is an optional mode of the kiosk editions (x86_64 kiosk and Raspberry Pi). With it switched on, bpplay first loads the whole selection into RAM (for a playlist with mixed sample rates, the whole segment), then switches the network interface off at link level, and only then starts playing. The SSH and NetworkManager services keep running, but the link itself is down, so the machine is cut off from the network while the music plays. In our hardware checks the link LED goes dark on the x86_64 kiosk, and on the Raspberry Pi the Ethernet RJ45 LEDs go dark.

When does the network come back? The network comes back when playback ends; the connection is usually available again within about half a minute on the x86_64 kiosk. A safety timer, set to the playback length plus 60 seconds, is only a backup in case bpplay is killed, so that the machine does not stay cut off.

Limits:

  • While Full Pure is active there is no remote control: the SSH session is cut when playback starts, and the machine can be reached again when the network returns.
  • Playback cannot be stopped by anything while Full Pure is active: the SSH session is cut and the local keyboard does not work during playback. The list plays to the end, and the safety timer, set to the list length plus 60 seconds, returns the network.
  • Full Pure cannot be combined with repeat mode: with repeat on, Full Pure cannot be switched on, and the other way round.
  • Network drives (NAS) are not indexed for search while Full Pure is on.
  • On a playlist that needs a change of sample rate or format, the network can come back briefly between the segments, because each segment is played by its own bpplay run.
  • Full Pure is switched on and off with the u key in the music selector. It is off by default, and the setting is remembered.
  • It is not available on the x86_64 desktop edition.

4.2 CPU isolation mode (selectable)

Isolation of the playback core is the same in every mode. The mode, set with the c key in the music selector, decides which other cores stay awake at all times (a power-management latency of 0 µs):

  • A: All cores stay awake. Highest power draw and heat, for well-cooled machines only.
  • B0: Only the playback core stays awake; the others may enter power-saving states. This is the default.
  • C0: The playback core and core 0, which handles interrupts, stay awake; the others may enter power-saving states.

A change takes effect when the next playback starts, and does not affect playback already running. On a machine with only two active cores, C0 and A are equivalent. The playback core itself is chosen by the boot-time measurement (see Boot-time measurement).

4.3 Music library and search

Drive selector. The m key opens the drive selector. It lists mounted drives, drives that are plugged in but not yet mounted, and network shares (NFS or SMB, mounted read-only); the five most recent shares are remembered. Local drives are mounted read-only. Choosing a drive that is already mounted asks The drive is already mounted. Check for changes? (y/N); answering y re-indexes it.

Global search. The / key searches all drives at once. Every word you type must appear in the name, regardless of accents and capitals. Enter opens the folder of the result, with the cursor on the file.

Index. The search index is stored and restored, so search is ready soon after start. Hidden files and macOS ._ files are left out. While a drive is being indexed, playback waits for the first pass to finish, and the status line shows the progress.

Excluding a drive. In the drive selector, the x key excludes a mounted drive from search and indexing: it is marked (excluded from search), stays in the selector, and can still be browsed and played. The same key switches it back.

4.4 Machine survey and DAC diagnostics

Press g in the browser for the machine survey and optimization report: machine and kernel, motherboard and BIOS, the isolated core and the CPU isolation mode, power management and scheduling, memory, the quiet profile and, where present, the Intel management engine. It is followed by DAC diagnostics: the formats the DAC advertises, the format actually used during playback, and the mixer and mute state. A short summary is shown at the first start. The report also shows whether the kernel command line contains isolcpus and nosmt; when nosmt is present, the switched-off hyperthreading siblings appear as offline cores, which is then the expected state and gives no warning.

4.5 Selecting storage

Press m at any time to open the drive selector.

  • It lists the drives that contain, or may contain, music: drives that are already mounted and drives that are plugged in but not yet mounted.
  • Move with the Up and Down arrows and select with Enter.
  • A drive that is not yet mounted is mounted automatically when you select it, read-only; no password is needed.
  • A Mount network share (NFS/SMB)... line lets you enter the address of a shared music folder on another machine (for example 192.168.1.10:/music for NFS, //192.168.1.10/music for SMB). The type is recognized from the form of the address. The share must already be set up on the NAS or the other machine: the music selector only mounts an existing, reachable share, read-only. Network shares are mounted read-only, as a guest: no user name or password is asked. A share that requires a password is not supported; enable guest (anonymous) read access for the music folder on the NAS. SMB shares are connected with SMB version 3.0, so a NAS that offers only SMB 1 or 2 cannot be mounted. Enter the share as //server/share.
  • If only one storage location is available, the selector skips this step.
  • Accessing network storage is slower than local storage and depends on the state of the network. The first indexing takes about 5 to 6 minutes per terabyte, depending on the speed of the drive.

4.6 Selecting the audio output

If several audio outputs are connected (for example the machine's built-in sound card and an external USB DAC), the music selector offers a choice at start: Up and Down arrows, Enter. If there is only one output, this step is skipped. The cursor starts on the first device that does not look like a built-in sound card (such as HDA Intel), so that pressing only Enter does not pick the built-in output by accident. If you are unsure, pick the one that shows a brand name, not the built-in sound card. The selected output is remembered; the o key opens the selection again.

4.7 Browsing and playback

  • If your music is organized into folders (albums), you first see the folder list: Enter opens a folder, Esc goes back. If all files are in one place, the track list appears at once.
  • Select tracks with Space; the n key clears the selection. Enter on a track does nothing, on purpose: only Space selects, so a selection cannot be undone by accident.
  • The memory usage counter at the bottom of the window shows how much of the memory your selection fills. At 70% usage the counter turns red, warning of the risk of overfilling. If a selection would not fit in memory, the music selector says so and does not start playback.
  • The p key loads the selection into memory and starts playback when loading is complete. Loading speed depends on the drive and, for a NAS, on the network.
  • Consecutive tracks with the same sample rate play as one gapless run. A track with a different sample rate starts a new run, so there is a short pause of one or two seconds at the change; this is not an error. To avoid clicks, the output is muted for a few tenths of a second at the change. While a run is playing, q stops the whole run and ends the playlist.

4.8 Known limitations

  • After mounting a new drive, wait about a minute before starting playback, so the first indexing pass can finish.
  • When loading DSD (DSF) files, the player briefly uses extra memory roughly equal to the size of the largest track. A list that nearly fills the loading limit may therefore, in rare cases, stop with an out-of-memory error on a machine with little memory. If this happens, select fewer tracks.

5What runs in the background

The bptune tuning layer runs automatically at boot: CPU governor set to "performance", Turbo Boost/Precision Boost disabled.

Kernel-level CPU-core isolation is active in this edition: the g machine survey on the trial image reports isolcpus is present in the kernel command line: yes. The boot-time measurement then chooses which isolated core plays the music.

Lockdown: no terminal emulator is installed in the system at all, the other virtual consoles (Ctrl+Alt+F2, etc.) are disabled, and the login shell IS the music browser; if it ever crashes, it just restarts, it never falls back to a raw command line.

5.1 Boot-time measurement

bptune measures the CPU cores at boot and chooses the playback core.

5.2 Quiet profile

When the quiet profile is on, the following background services are stopped for playback: cron, avahi, rpcbind, polkit, udisks2, the periodic maintenance timers, the udev control sockets, the user session manager, and Wi-Fi supplicant services when no Wi-Fi connection is active. These are never stopped: journald, ssh, NetworkManager, dbus and logind. If any of them is not running after the stop, everything is restored at once. The profile is switched off again when playback ends. Connected drives: during playback the hard disks and SATA SSDs connected to the machine, internal and external USB, are put into standby, and internal NVMe drives are put into their deepest safe low-power state, but only if the drive supports more than one power state; otherwise they are left as they are. Any later access, such as browsing to the next album, wakes them up automatically. The boot stick is left out. Only the power state changes; nothing is written to the drives. During playback, the system spins down the hard disks connected to the machine, including external USB drives, because the music is already in memory. Nothing is written to the drive. It spins up again the next time it is accessed, which can take a few seconds. On the Raspberry Pi the SD card is kept awake instead; that does not apply here.

Stopping playback and the local keyboard: during playback the keyboard attached to the machine does not work (this is part of the quiet profile: the login service on the machine's own screen is stopped). In normal mode (Full Pure off) playback can be stopped over SSH (with the q key of the player). In Full Pure mode playback cannot be stopped by anything: the list plays to the end, and the safety timer returns the network after the list length plus 60 seconds.

5.3 Language editions

bpplay is released in Hungarian (HU) and English (EN) editions. The language is fixed in the image: it sets the texts of the music selector and of bptune, the default music folder (Zenék in the HU edition, Music in the EN edition) and the time zone (Europe/Budapest in HU, UTC in EN). On the desktop edition the keyboard layout follows the language (hu or us).

5.4 What survives a reboot

At a clean shutdown the stick's settings area saves only what is on a fixed list, and restores it at the next start: the music selector's settings (including favorites, saved playlists and the selected output), the SSH host key, the trial state, the network connections, the DAC mixer state, and the tuning and machine-survey results; the search index is stored there as well. Nothing else is saved. Shut the machine down with q at the top level of the music selector, and do not pull the stick or the power while it runs.

5.5 Signal path and the sound driver

bpplay's design goal is for sound to travel from the file's loading into memory to the DAC through the fewest, best-documented steps possible. When an integer source meets an integer DAC format, this means zero arithmetic conversion.

The phrase "the sound driver performs the last step" in the signal-path messages refers to the audio subsystem of the underlying operating system (ALSA on Linux).

5.6 What bpplay and bptune are

bpplay is a command-line, bit-perfect audio file player for Linux and macOS. It has no graphical interface, no volume control and no equalizer, on purpose. Its goal is one thing: to deliver the contents of the music file unchanged, by the shortest path with the fewest conversion steps, to the DAC. In this edition you never start it yourself: the music selector runs it in the background for the tracks you select.

Whenever possible it plays in integer mode: the integers stored in the file reach the sound card without a bit shift or conversion. When that is not possible (for example the source is in float format, or the DAC does not support the bit depth of the source) the program says so clearly. It never silently hides a format deviation, and if a DAC does not return exactly the requested sample rate, it retries instead of quietly accepting a wrong rate.

DSD: bpplay sends DSD directly (native DSD) when the DAC supports it, and otherwise packs it into PCM frames (DoP). Which of the two works depends on the DAC chip and the DAC design, not on the computer; the machine survey and DAC diagnostics (4.4) show what your DAC advertises.

bptune is a system-tuning tool that sets Linux kernel and hardware options for low-latency, glitch-free playback and handles background services that would interfere with it (see 5 and 5.2). On the kiosk image it is already configured; there is nothing for you to do with it.

6Trial period: 15 days

This is a time-limited trial, valid for 15 days from your first real boot. The countdown is tied to the USB stick itself, not the machine you boot it on; so if you try it on several machines, the remaining time carries over.

A new image is a new trial: if the image is newer than the stored start, the 15 days count from the image. An image built more than 90 days before it is first started will not start. The music selector shows Trial: N days left on the information line below its header.

  • Turning back the clock does not extend the trial; the system detects this.
  • On expiry, the machine shuts down automatically after a short message; this is not a bug, it is the trial's intended end (the same thing happens if you press q at the top level).
  • The trial is not extendable; to try it again after it expires, get in touch with whoever gave you the USB stick for a fresh image.

8What's new: R1

  • License and machine ID. The top of the g report in the trial edition shows the machine ID (64 hex digits), which is needed to request a license; it is derived from the motherboard's factory identifier. The final image is bound to one computer and works without a time limit; the check uses no internet connection and does not depend on the computer's clock. How: how to request a license.
  • New core management mode: A (c menu). During playback the playback core works continuously and never goes to sleep, while a guard on core 0 checks that system threads still get processor time. If the computer or the DAC is not suitable, the player falls back to A0 mode and shows the reason. The "A" mode of RC22 is now called A0; its behaviour is unchanged.
  • Protections before playback. If the selected output is the motherboard's built-in audio while a USB DAC is also connected, a confirmation question appears. A DSD file cannot be started on an output that cannot play DSD. Before loading, the program adds up the memory needed, and if the tracks certainly do not fit, it loads nothing and shows how much RAM would be needed and how much is available.
  • Lower load during playback (bpplay 1.6.1). The status line no longer counts continuously, so fewer threads work: on a track change it shows the track number and the length of the track and of the list, on a key press the current playback time. The low-latency mode of the USB audio driver is switched off, and the indexing crawler runs on a single core.
  • Start-up and indexing. The quiet profile and core restore at start-up take at most 10 seconds, and the interface starts after that anyway. After an unexpected stop, the quiet profile and core management are restored at the next start. Playback can be started after the first indexing pass has finished, and the message that Full Pure and repeat cannot be used together stays visible until the next key press.
  • Locked-down kiosk, trial. The local console has no tmux prefix, command line or new windows (RC22 had them). The header shows when the trial record is damaged; the player then does not start next time.
